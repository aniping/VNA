# ZNB 功能规范与页面 UI 一致性门禁

## 1. 目标

VectorNetworkAnalyzer 的产品功能和页面 UI 以 R&S ZNB User Manual Version 74 为主要基线。项目允许分阶段实现，但每个宣称完成的功能必须严格复现手册描述的功能语义、操作路径和页面表现，不能用名称相似或大致可用的替代实现冒充完成。

本门禁约束需求分析、设计、编码、测试、审核和最终发布验收。

## 2. 依据优先级

发生冲突或歧义时，按以下顺序处理：

1. 用户当前明确指令和用户提供的参考截图。
2. 本地 `ZNB_UserManual_en_74.pdf`。
3. ZNB 实机行为或用户确认的实机证据。
4. 本地 `ZNA_UserManual_en_41.pdf`，仅用于 ZNB 未覆盖的共同测量语义。
5. 现有项目文档、测试和代码。

不得用 ZNA 的双屏布局、控件结构或默认行为覆盖 ZNB。现有实现与手册不一致时，现有实现不是正确性依据。

ZNB v74 共 1786 页。取证时不能只凭一张界面截图推断业务行为，应同时检查 Getting Started、Concepts and Features、GUI Reference、Remote Control/Command Reference 以及适用的 Programming Examples，并在规格记录中写明准确章节和页码。

## 3. 适用范围

门禁覆盖 ZNB 手册描述的所有适用于本产品的内容，包括：

- Preset、Channel、Trace、Measurement、Sweep、Trigger、Calibration、Marker、Display、File 和 System 功能。
- Hardkey、Softtool、菜单、对话框、工具栏、状态栏、图表、坐标轴和提示信息。
- 默认值、单位、参数范围、能力限制、启用/禁用条件和错误反馈。
- 鼠标、触摸、键盘和远程命令触发后的状态变化与完成语义。
- 多 Channel、多 Trace、多 Window 和不同测量/格式组合下的联动。
- 文件、SCPI 和远程接口中由手册承诺的等价行为。

阶段计划可以决定先实现哪些内容，不能降低已选中切片的一致性要求。

## 4. 开工前功能规范门禁

每项用户可见功能编码前，必须建立一份可核验的规格记录，至少包含：

| 字段 | 要求 |
| --- | --- |
| 功能标识 | 稳定名称，能够在任务、测试和回报中引用 |
| 手册依据 | ZNB v74 章节、印刷页码和 PDF 页码；必要时记录图号或表号 |
| 用户入口 | Hardkey、Softtool、菜单、对话框、SCPI 或文件入口的完整路径 |
| 前置条件 | 当前 Channel、活动 Trace、能力、权限、校准或运行状态 |
| 默认状态 | Preset 值、选中项、单位、显示内容和初始焦点 |
| 输入合同 | 参数类型、单位、范围、步进、特殊值和格式 |
| 状态转换 | 操作前状态、提交时机、生效边界、完成状态和可取消性 |
| 数据影响 | 是否重新采集、重新处理、仅重绘或影响后续 Sweep |
| 错误语义 | 非法输入、资源冲突、硬件故障和不可用能力的表现 |
| UI 合同 | 页面区域、控件顺序、尺寸关系、文字、图标、颜色和交互反馈 |
| 远程等价 | 手册存在 SCPI/远程语义时，说明与本地操作如何共享业务核心 |
| 验收步骤 | 自动测试、发布版实机操作、截图和网络/日志证据 |

手册未说明、不同章节冲突或实机行为不确定时，必须停止猜测并向用户确认。

## 5. 功能实现一致性

一项功能只有同时满足以下条件才能标记为完成：

- 入口位置、名称、参数和默认值与 ZNB 一致。
- 操作修改正确的业务对象，不通过创建额外 Channel、Trace 或 Window 模拟效果。
- 状态转换、生效时点、Sweep/Trigger 行为和完成语义一致。
- 本地 UI、SCPI、远程接口复用同一业务真值，不分别实现规则。
- 通过真实 HTTP、WebSocket 或 SCPI 入口操作后，能够重新读取权威状态或结果，证明入口不是前端空壳。
- Measurement、Trace、Window、校准、文件和硬件职责没有被错误合并。
- 适用的参数范围、单位、能力判断、错误和恢复行为一致。
- 数据路径仍符合产品平台总纲，不能为复刻页面绕过正式测量链路。

只有页面、按钮或文案，没有真实业务语义，不算完成；只有后端接口，没有手册规定的操作入口和反馈，也不算完成。

## 6. 页面 UI 1:1 门禁

页面验收必须从正式 `release/VectorNetworkAnalyzer` 目录启动服务，使用真实 `127.0.0.1:8080` 页面而不是开发 Mock，并在 1280×800、100% 缩放下进行真实浏览器操作。至少逐项核对：

- 顶层区域划分、测量工作区、控制区、工具栏、菜单栏和状态栏的几何关系。
- Hardkey 分组、列数、顺序、大小、间距、文字换行、图标和禁用状态。
- Softtool 的层级、返回路径、选中态、参数编辑器、分页和上下文变化。
- Diagram 数量、布局、活动标识、Trace 信息条、Channel 状态行和 Window 标识。
- LogMagnitude、Phase、Smith 等格式的网格、坐标轴、刻度、单位、参考值、曲线颜色和裁切行为。
- 弹窗、提示、错误、等待、断线、无数据和恢复状态是否位于正确区域且不遮蔽必要内容。
- 鼠标、触摸、Enter、Space、焦点和活动对象切换是否符合手册操作顺序。

验收应保存手册页码、实际操作步骤和发布版截图证据。自动化 DOM/CSS 测试用于防回归，不能替代真实浏览器目视和交互验收。

涉及响应式布局时还应补充项目支持的较大分辨率检查，但较大屏适配不能改变 1280×800 的 ZNB 基准几何和信息层级。浏览器网络记录必须证明页面调用真实命令或订阅正式数据流。

未经用户确认，不得用“现代化”“更美观”“网页习惯”或实现方便为理由改变 ZNB 的信息层级和操作方式。

## 7. 未实现和部分实现

功能状态统一使用：

- `未实现`：入口隐藏，或按当前阶段要求以原生禁用状态显示；不能产生假操作。
- `部分实现`：必须列出已符合和未符合的手册条目，不能称为完成。
- `已实现待实机验收`：自动测试通过，但尚未完成 release 浏览器操作。
- `符合`：功能规范和 UI 门禁全部通过。
- `批准偏差`：用户明确接受与手册不同的行为，并已登记原因和影响。

禁用占位不能发送请求、修改本地假状态或创建没有正式后端语义的数据。

## 8. 偏差确认

因产品定位、硬件能力、法律与商标、跨平台限制或用户主动改进而需要偏离 ZNB 时，必须：

1. 指出 ZNB v74 的具体章节和原行为。
2. 描述拟修改的功能与页面差异。
3. 说明原因、用户影响、兼容性和替代方案。
4. 在编码前取得用户明确确认。
5. 在相关 ADR、规格记录和验收报告中登记该偏差。

不得复制手册截图、R&S 商标或受保护品牌素材；应使用项目自有素材复现功能、结构和交互。品牌素材限制不构成任意改变布局或行为的理由。

## 9. 完成回报格式

每个涉及 ZNB 功能或页面的大需求，交付说明必须包含：

```text
ZNB 功能规范门禁：PASS / FAIL / 批准偏差
手册依据：章节、印刷页码、PDF页码
发布版实机验收：PASS / 未执行
页面 UI 1:1 门禁：PASS / FAIL / 批准偏差
未实现或部分实现项：明确列表
```

任一必需项为 `FAIL` 或 `未执行` 时，不得向用户描述为最终完成。
