# 采用结构化可观测性接口与双日志输出

## 决策

建立独立的可观测性接口，由应用层和协议适配器提交结构化事件，
由 `infrastructure/logging` 提供实现。领域模型不依赖日志接口，也不直接
产生日志副作用。

首个实现同时输出：

- 控制台 JSON Lines，供开发和进程托管工具采集。
- 滚动 JSON Lines 文件，单文件上限 10 MB，保留 10 个文件。

基础设施默认保留上述双输出，也允许组合根为控制台选择人类可读格式。
便携发布版使用这一部署覆盖：同一 `LogEvent` 在控制台形成简短标准行，在滚动
文件中保持权威 JSON Lines；根启动脚本只输出位置提示，不复制事件真值。
独立 `stderr` 继续承担紧急失败报告，写入或刷新失败由调用方通过该通道报告。

日志目录由组合根通过平台适配器确定：Windows 使用用户 Local App Data
状态目录，Linux 优先使用 XDG state 目录。测试必须注入临时目录，不读取
开发机固定路径。

便携部署目录 `release/VectorNetworkAnalyzer/` 是上述用户状态目录规则的
显式覆盖：组合根将日志写入发布根中与 `bin/` 相邻的 `logs/`。该目录只由
明确的 install/package 步骤组装；普通开发 build 只产生中间产物，不得创建
或部分更新 `release/VectorNetworkAnalyzer/`。

## 结构化字段

每条记录至少包含 UTC 时间、级别、稳定事件名和适用的关联标识。命令日志
必须包含 `command_id`、`session_id`、`instrument_id`、
`state_revision` 和 `status`；后续按事件补充 `operation_id`、
`sweep_id`、`frame_id`、`measurement_id` 和 `trace_id`。

默认禁止记录完整请求体、认证信息、测量数组和未声明的文件内容。自由文本
只能作为说明字段，不能替代稳定事件名和结构化错误码。

Web 协议适配器只在统一命令入口完成 dispatch 后记录一次 `web.command.*`。
读请求、静态资源和连续显示帧不产生日志，避免把低频审计事件与采集热路径混合。

## 执行语义

当前实现使用同步、线程安全的 spdlog sink。`Logger::write` 返回 true 表示事件
已完成编码并尝试写入全部已配置 sink；编码、单条大小或终端 sink 故障返回
false。sink 一旦失败，后续写入继续返回 false，避免把已失去权威文件输出的
日志器伪装为健康。`Logger::flush` 刷新日志库和 C++ 流缓冲，不表示 fsync。

同步语义消除了应用自研队列、丢弃策略、后台线程和超时完成栅栏。它也意味着
文件 I/O 可能阻塞调用线程，因此在经过性能测量和单独设计前，控制执行器与
采集热路径不得直接提交高频日志。如果后续确实需要异步吞吐，应采用日志库的
原生异步能力并重新明确可观察的丢弃策略，不在其外部重建第二套队列。

正常退出时，组合根在最后一条生命周期事件后显式 flush；返回 false 时通过不
依赖该日志器及其 sink 的最小 `stderr` 通道报告。同步文件 I/O 仍无法跨平台
强制取消，因此本决策不把 flush 描述为硬实时截止时间或持久化保证。

首版发布不承诺强制结束进程或按下 Ctrl+C 必然完成 flush。强制结束可能绕过
用户态清理；Ctrl+C 也只有在信号适配和退出编排完成实现与验证后，才能声明
遵守上述可靠退出协议。

spdlog 作为 compiled static 库只存在于 `infrastructure/logging` 实现中，
其类型、宏和格式化接口不得泄漏到可观测性接口或业务模块。结构化 JSON 仍由
项目的强类型事件序列化器产生，sink 只负责线程安全输出与文件轮转。

## 结果

该决策增加一个轻量基础设施依赖和跨平台目录解析成本，但删除了自研并发日志
状态机，使 Web、SCPI、仿真、数据处理和未来 Driver Host 可以通过同一小型
接口使用稳定关联模型，并支持离线故障追踪和回放。
