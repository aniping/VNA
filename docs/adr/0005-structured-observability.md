# 采用结构化可观测性接口与双日志输出

## 决策

建立独立的可观测性接口，由应用层和协议适配器提交结构化事件，
由 `infrastructure/logging` 提供实现。领域模型不依赖日志接口，也不直接
产生日志副作用。

首个实现同时输出：

- 控制台 JSON Lines，供开发和进程托管工具采集。
- 滚动 JSON Lines 文件，单文件上限 10 MB，保留 10 个文件。

基础设施默认保留上述双输出，也允许组合根显式禁用普通控制台 JSON。
便携发布版使用这一部署覆盖：权威结构化事件只写滚动文件，根启动脚本输出
简短的人类启动提示，独立 `stderr` 继续承担紧急失败报告。禁用普通控制台时
没有可伪装成功的紧急 JSON sink；高严重度过载仍按拒绝及 terminal failure
语义处理。

日志目录由组合根通过平台适配器确定：Windows 使用用户 Local App Data
状态目录，Linux 优先使用 XDG state 目录。测试必须注入临时目录，不读取
开发机固定路径。

便携部署目录 `release/VectorNetworkAnalyzer/` 是上述用户状态目录规则的
显式覆盖：组合根将日志写入发布根中与 `bin/` 相邻的 `logs/`。该目录只由
明确的 install/package 步骤组装；普通开发 build 只产生中间产物，不得创建
或部分更新 `release/VectorNetworkAnalyzer/`。

## 结构化字段

每条记录至少包含 UTC 时间、级别、稳定事件名和适用的关联标识。命令日志
必须包含 `command_id`、`session_id`、`instrument_id`、
`state_revision` 和 `status`；后续按事件补充 `operation_id`、
`sweep_id`、`frame_id`、`measurement_id` 和 `trace_id`。

默认禁止记录完整请求体、认证信息、测量数组和未声明的文件内容。自由文本
只能作为说明字段，不能替代稳定事件名和结构化错误码。

## 执行语义

日志实现使用有界队列与专用写入线程，不能让磁盘 I/O 阻塞控制执行器或
采集线程。队列过载必须累计丢弃计数；Warning 和 Error 不得静默丢弃。
进程正常退出时必须进行有界 flush，不允许无限等待。

显式、带有限截止时间的 flush 是可靠退出协议。组合根必须先停止或隔离所有
仍可能调用 `Logger::submit` 的生产者，再执行最终 flush。只有该 flush 返回
true，组合根才能按正常路径销毁日志器；true 表示调用前已接受的事件完成双
输出并刷新 C++ stream，不表示执行 fsync。任意 `std::ostream` I/O 都无法
跨平台强制取消，因此析构只执行 best-effort stop，不是可靠交付或有界退出
协议。

若最终 flush 返回 false，组合根必须通过不依赖该日志器及其两个 sink 的最小
紧急通道报告失败，并转入平台受控的有界强制退出策略，不得销毁或等待可能仍
阻塞在 I/O 的日志器。该强制退出策略由后续组合根集成明确实现。

首版发布不承诺强制结束进程或按下 Ctrl+C 必然完成 flush。强制结束可能绕过
用户态清理；Ctrl+C 也只有在信号适配和退出编排完成实现与验证后，才能声明
遵守上述可靠退出协议。

具体日志库属于基础设施实现选择，不得泄漏到可观测性接口或业务模块。

## 结果

该决策增加一个基础设施模块和跨平台目录解析成本，但使 Web、SCPI、仿真、
数据处理和未来 Driver Host 使用相同关联模型，并支持离线故障追踪和回放。
