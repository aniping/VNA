# 分离控制流、正式数据流与通知流

> 状态：已由架构定案；Buffer ABI、容量与目标平台仍受 E4/平台门禁

方法级 accepted/terminal、lease、Drain 与读句柄规则见[跨层 Interface 契约](../design/interface-contracts.md)。

VNA 同时存在三条正交流：Command/revision/Operation 构成控制流，A/B/Stage/C 与校准观测构成正式数据流，Catalog commit/EventCursor 构成通知流。三者可以引用相同的 typed ID，但不得互相替代：Operation 只拥有工作、预算和执行 lease；Event 只携带有界 metadata/软引用，可以显式 gap 且不保活数据；QueryTicket 只拥有某个调用者的 waiter、ResultPin/Reader 能力。

正式数据统一由 Measurement Data Store/SnapshotCatalog 管理不可变 Buffer、typed parent closure、QualityPlane、retention 与 tombstone。只有 Control Executor 能取得 `DomainCommitPermit`；Acquisition/Processing/Calibration worker 只能消费冻结输入并返回 `Succeeded | Failed | Draining` typed terminal，只有 Success 携带持有 `CandidateCommitLease` 的 `PublicationCandidateBatch`，不能直接写 Catalog、更新 Head 或发布 Event。Persistence/Diagnostics 使用同样的 terminal ownership 规则返回 Load/Commit/Export/Diagnostic 结果，任何会改变在线 Catalog 的结果都必须先转成经 Control Executor 验证的领域 candidate，不能由 worker 直接发布。异步计算派发前原子取得全部父输入的 `PinnedInputSet`，不可中断任务转 Drain 时连同输入、输出 reservation 和预算一起转移；worker return 后候选租约持续到 commit/abort，不留下所有权缺口。

Control Executor 把可选候选批、有类型的 `DomainCatalogPatchSet`、Head、Operation/fence、Instrument Status Register、SCPI Session State、WaitRegistry、QueryTicket/ResultPin、EventJournal 和 retention patches 组装为一个 `DomainCommitBundle`，交给公开 `InstrumentStore::commit` 全有或全无提交；Measurement Data Store 与 Domain Commit Coordinator 只是其内部实现。Domain Catalog patch 覆盖 Instrument/Channel/Calibration/Analysis/Display 等小型可变 revision，不得变成无 schema 的 key/value。B、对应 accumulator snapshot、`ChannelAverageHead`、`ChannelMeasurementHead` 与完成状态必须同批可见；CorrectionSet publication 与 CalibrationSession terminal、Recall 的 Instrument revision 切换也必须同批；只有匹配 current-input token 的 Live C 才把 C closure、`TraceAnalysisHead` 与发布事件同批提交，历史 B/Stage exact query 默认只发布/返回 C 而不倒退 Head。direct Ready admission 在同一 commit 创建 Ticket 并取得精确 ResultClosure pin；Pending Query 则在 join 前为每个 caller 独立安装 `PendingResultPinReservation`，completion bundle 只转换仍有效 reservation，所以单个 waiter 的 quota/cancel/TTL 不回滚共享 publication 或其他 Ticket。`open_read` 把 Ready→Reading 与 ResultPin→ReaderLease 原子转换，传输 terminal 再把 Reading→Consumed/Failed/Abandoned 与 ReaderLease 释放同批提交。任何异步 Operation/Pending Ticket/Drain 首次可见前都随初始 commit 安装 `LifecycleTerminalReservationSet`；publication commit 失败时旧 reservation 仍有效，Control Executor 必须 reconcile 已有终态或 state-only commit Failed，普通错误不得留下 Pending/Publishing，只有 Store 完整性故障才 fail-stop。任何提交失败都不得留下半套 Snapshot、半更新领域 revision、已推进 Head、状态/唤醒缺口、Ready ticket 或孤立 Event。

必达采集后继不允许 Store 充当 Runtime capability 的浅透传层。非 A-only Sweep 在 RF start 前将 Store pins/output/新 A join reservation 与 Runtime `ReservedWorkDispatch` 聚合为 `AcquisitionContinuationOwner`；A commit 前由 L2 拆成 `ContinuationStoreJoinOwner` 和 `ContinuationRuntimeEscrow`。只有 Store owner 进入 bundle，Runtime escrow 与 Preview finalization owner 在同步 commit 期间仍由 L2 持有；Store 成功只返回 `ContinuationStoreHandoff`，L2 再组合派发。因此 `DomainCommitBundle/CommitResult` 的类型图中禁止 `ReservedWorkDispatch`、`WorkDispatchPermit`、`RuntimeCompletionRegistration` 和 `PreviewFinalizationOwnerSet`。A-only 不创建空后继 handoff。

EventJournal 也不直达 L1。L2 通过 `InstrumentStore::begin_event_feed` 原子建立 replay-cut→live feed，再做 ACL/filter/access-revision 投影，L1 只编码授权 Watch mailbox。`ResultPinLease` 同样一直留在 Store；`open_result` 在 Store 内部把它转成只封装在 opaque `QueryReadHandle` 内的 ReaderLease，L1/L2 都不接触裸 lease。

采集侧同样遵循唯一所有权：Board Adapter 把 move-only `AcquisitionChunkLease` 交给有界 Acquisition Ingress，Network Observation Builder 是唯一长期拥有者。底软 buffer 不能转移时在回调边界复制一次到预留 BufferPool；Preview 只能读取有界 `ChunkReadView` 或拥有独立、可丢弃的 `PreviewTile`。正式 chunk 不能静默丢弃，Preview 拥塞也不能反压采集。

该决策使 Web/SCPI/File 只在线缆编码和会话语义上不同，无法各自维护“当前数组”；也使事件丢失、慢客户端、retention、取消与 Drain 不会破坏正式事实或完成 fence。代价是必须实现强类型 ID、InstrumentStore permit、Head、lease 配额、候选批和全有或全无领域提交及相应竞态测试。职责落层见 [分层架构与跨层流动](../design/layered-architecture.md)，完整所有权规则与验收场景见 [端到端数据流与生命周期契约](../design/data-flow.md)。
