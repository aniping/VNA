# 采用乐观并发控制、幂等命令与结构化错误

## 决策

第一阶段为每台 Instrument 建立 Local 和 Remote 两种控制权状态。Local
状态下，Web UI 可以修改仪表；多个 Web 请求由乐观版本控制避免静默覆盖。
收到首条有效 SCPI 命令后进入 Remote 状态，唯一的活动 SCPI 会话获得修改
权，Web UI 保持连接和观察能力但只能读取。

Web 修改命令必须携带客户端读取到的 `expectedStateRevision`，版本不匹配
时返回冲突。所有状态修改仍由同一个控制执行器串行提交，并共享同一个单调
递增的 `stateRevision`。

同一时间只允许一个活动 SCPI 控制连接。第二个连接返回资源忙并关闭，不创建
第二套输出队列、错误队列或状态寄存器。Local takeover 释放并断开活动 SCPI
会话，使 Web UI 恢复修改权；它不隐式中止已经启动的 Operation。

SCPI 协议没有版本字段，其适配器在命令进入串行控制执行器时使用当前状态，
不通过读取快照再拼接一次 Web 请求。

## 命令幂等

命令以 `(instrument_id, session_id, command_id)` 作为幂等键。在同一服务
进程生命周期内：

- 相同键和相同命令内容重复到达时，返回第一次执行的结果，不再次修改状态。
- 相同键对应不同命令内容时，返回结构化的命令标识重用错误。
- 幂等结果存储必须有容量上限和可观测的淘汰计数，不能无限增长。

SCPI 适配器为每条解析完成的命令生成内部 `command_id`；Web 客户端提供可在
重试时复用的 `command_id`。

## 结构化错误

领域错误码必须保留到应用命令结果。应用层使用稳定的结构化错误码区分非法
参数、实体不存在、版本冲突、错误 Instrument、命令标识重用、操作失败和
取消。协议适配器只负责映射：Web 映射为 HTTP 状态和 JSON，SCPI 映射为
错误队列、ESR/STB 状态和协议响应。

禁止在协议适配器中重新判断扫频范围、实体引用或 Operation 终态。

## 暂不承诺的信封字段

同步配置命令尚未形成排队优先级和超时语义。现有 `timeout` 和 `priority`
不得继续作为看似生效的接口字段；在实现 OperationManager 时，将 deadline、
取消和调度优先级放入明确的 Operation 接口并通过对应测试后再公开。

## 结果

该决策使多个入口复用相同业务逻辑，同时避免本地与远程控制互相覆盖，并避免
网络重试重复创建 Channel、Measurement 或 Trace。代价是控制面需要显式的
Local/Remote 状态、会话释放流程和有界幂等结果存储；应用错误接口也必须在
SCPI 接入前完成一次兼容性调整。
