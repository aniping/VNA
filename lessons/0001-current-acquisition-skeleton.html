2026-08-01 当前主线：原始层已经采集二端口完整 receiver 数据；已接通的发布层仍固定输出默认 S21、Log Magnitude、单 Trace。多 Trace/Phase/Smith 的动态发布器尚未集成。

先记住这张骨架

1. Source仿真生成 reference 与全部 response receiver
2. Acquisition唯一 worker 校验并覆盖 latest 原始帧
3. Publisher等待新 sequence，合成 S21 并投影 dB
4. Repository只保留每条 Trace 最新完整显示帧
5. Web + VueWebSocket 推送，前端按 sequence 替换曲线

这不是五次采集。只有第 2 段拥有原始数据源；后面四段都是消费、转换或传输。

证据一：浏览器没有启动采集

入口在 apps/vna-server/main.cpp 的 runServer()。对象按以下顺序构造：

179–189
准备 preset、仓库与发布目录。
191–192
构造 ContinuousAcquisition。
193–196
构造 ContinuousTracePublisher。
205–213
最后才构造并监听 WebApi。

ContinuousAcquisition 的构造函数在 continuous_acquisition.cpp 72–79 行立即创建 std::jthread。因此，服务对象一创建，采集就开始；有没有浏览器连接不影响它。

证据二：一次循环到底做什么

  1. run() 从 sequence 1 开始循环。
  2. source_(plan, sequence, token) 调用仿真源。
  3. 采集层校验端口数、源端口、点数、response 数和有限值。
  4. 校验成功后附加 frame/sweep/sequence 身份。
  5. publish() 覆盖唯一的 latest_，再唤醒等待者。
  6. 以 preset 的 100 ms 最短周期节拍进入下一轮。

关键词是“覆盖”。原始采集层没有历史队列；处理线程慢时允许跳过中间帧，但 sequence 绝不倒退。

原始数据此时长什么样

raw_receiver.hpp 把一帧组织为 RawReceiverPayload → RawSourceState → RawReceiverSample。每个 sample 同时保存激励端参考接收机 reference 和所有响应端 responses。

它故意没有 Channel、Measurement 或 Trace 身份。原因是同一份二端口原始数据以后可以派生 S11、S21、S12、S22，不应为每条 Trace 重扫一次。
