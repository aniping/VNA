# 前端与 ZNB 体验规则

本文件补充仓库根 `AGENTS.md`。修改 `frontend/` 前必须完整阅读 `docs/znb-conformance-gate.md` 以及任务涉及的 ZNB v74 手册章节。

## 依据与边界

- 参考优先级为：用户当前明确指令与截图、ZNB v74、用户确认的 ZNB 实机证据、仅用于共同测量语义补充的 ZNA v41、现有实现。
- 不得用 ZNA 的双屏布局、控件结构或默认行为覆盖 ZNB；现有页面也不是正确性依据。
- 手册不明确、章节冲突或实机行为不确定时停止猜测并询问用户。
- 不复制手册截图、R&S 商标或受保护品牌素材；使用项目自有素材复现功能、结构和交互。

## 实现要求

- UI 必须展示后端权威状态和处理后的正式测量数据；不得在前端复制领域规则、S 参数计算、格式换算或伪造业务状态。
- Hardkey、Softtool、菜单、对话框、工具栏、状态栏、Diagram、坐标轴、文字、图标、颜色、间距和禁用状态按 ZNB 证据实现。
- 没有真实业务行为的入口必须隐藏或原生禁用，不能发送请求、修改本地假状态或创建空壳对象。
- 网络异常、无数据、等待和恢复状态不得遮蔽仍应显示的 Diagram 网格、轴与可恢复控制。
- 交互必须覆盖任务适用的鼠标、触摸、键盘、焦点和活动对象切换；可访问性语义不得与视觉状态冲突。
- 不得以“现代化”“更美观”“网页习惯”或实现方便为理由改变 ZNB 的信息层级和操作方式，除非用户预先批准偏差。

## 验证要求

- 自动化测试覆盖状态映射、交互、几何和数据契约，但不能替代实机验收。
- 最终验收必须从正式 `release/VectorNetworkAnalyzer` 启动真实服务，在 `127.0.0.1:8080`、1280×800、100% 缩放下操作。
- 验收必须核对页面几何、入口顺序、默认值、活动态、三种图形格式、坐标轴、断线恢复和真实网络请求，并确认浏览器 console 无非预期 warning/error。
- 交付说明按 `docs/znb-conformance-gate.md` 第 9 节报告手册依据、发布版实机结果、UI 门禁和未实现项。
